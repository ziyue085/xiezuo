# 对照实验与评价方法

## 0. 一句话

同一个模型、同一份任务书，A 组裸写，B 组按 skill 写；产出匿名交叉，四位评审盲评，另有一套脚本做表层与硬约束检查。

**结论见 `RESULTS.md`。方法上的问题见本文第 8 节——那一节比结果重要。**

---

## 1. 可证伪的假设

实验前先写下要检验什么，避免事后找解释：

| 编号 | 假设 | 被什么推翻 |
|---|---|---|
| H1 | 启用 skill 后，"继续阅读意愿"显著提高 | B 在该维度胜率 ≤ 50% |
| H2 | 人物会更具体（有欲望、有行为逻辑、有个人语式） | 人物维度无优势 |
| H3 | 情绪更多由证据产生，而非直接命名 | 情绪维度无优势，或脚本显示 B 的"情绪命名"密度更高 |
| H4 | 堆砌与注水减少 | 注水维度无优势 |
| H5 | 表层节奏（句长变化）改善 | 脚本显示 CV 无差异 |
| H6 | 任务约束的遵守度提高 | 约束契合维度无优势，或硬约束检查 B 更差 |

按用户要求，**没有预设 B 必然优于 A**。H1–H6 中任何一条被推翻，都要如实写。

---

## 2. 变量控制

| 变量 | 控制方式 |
|---|---|
| 模型 | 同一个模型（DeepSeek-V4.1-Flash），写作代理与评审代理都在隔离上下文中运行 |
| 任务 | A/B 使用**逐字相同**的 prompt 文件（由 `build_prompts.py` 从同一份 `scenarios.json` 生成） |
| 输出格式 | 两组都被要求"只输出正文，不解释过程" |
| 篇幅 | 同一场景给同一字数区间 |
| 唯一差异 | B 组多一段：读 `SKILL.md`，按路由加载参考，按其中的方法完成 |

**没有控制住的**：写作代理的执行顺序、随机性、模型自身的长度倾向（B 组普遍长 2%–20%）。见第 8 节。

---

## 3. 测试场景（10 个，原创）

| ID | 类型 | 考点 |
|---|---|---|
| S01 | 人物离别（小说） | 二十年的父女，能否写出只属于这两人的说话方式与动作 |
| S02 | 市井生活（小说） | 价格、斤两、时间能否撑住一个场景 |
| S03 | 历史人物冲突 | 史实边界与戏剧张力能否同时成立 |
| S04 | 历史事件叙述 | 规模感与史料纪律，避免空泛的苦难抒情 |
| S05 | 权谋对话 | 权力关系能否只靠台词与动作传递（禁写心理） |
| S06 | 幽默与反转 | 笑点是否来自人物自欺与信息差；反转是否回溯得通 |
| S07 | 现实主义 | 流程与数字的真实感；克制，不给结论 |
| S08 | 文化与人生散文 | 有无认知增量；联想是否被材料牵引 |
| S09 | 润色·小说片段 | 保真：人物、事实、视角、篇幅不动 |
| S10 | 润色·历史叙述 | 能否识别伪造出处与时代错置 |

每个场景在 `scenarios.json` 里带 `checks` 字段，写明可程序化验证的硬要求（最小字数、必须保留的事实、必须清除的词、最少数字数、最低对话占比）。

场景设计的三条原则：

1. **不给写作术语**。任务书用日常语言写（"不要写依依不舍"），不出现"落差""潜台词""承重细节"——否则 A 组也被提示了方法。
2. **带约束**。约束是检验"是否听话"的手段，也是真实写作的常态。
3. **留出失败空间**。S01、S06、S07 都是容易写坏的类型（离别易煽情、幽默易散、现实易说教）。

---

## 4. 生成流程

```
experiments/tools/build_prompts.py   → prompts/S01_A.txt … S10_B.txt
（6 个写作代理，各写 2–4 篇，写入 runs/<sid>/<arm>.md）
experiments/tools/blind.py           → blind/<sid>/{甲,乙}.txt + key.json
```

写作代理不知道自己在做实验，也不知道另一组的存在；B 组代理被要求只读 skill 文件，不得查看 runs 目录里已有的成品。

---

## 5. 盲评设计

### 5.1 四位评审，两个控制

| 评审 | 材料 | 提示词 | 作用 |
|---|---|---|---|
| judge1 | blind（甲/乙 随机） | 中性 | 主判定 |
| judge2 | blind（同上） | 中性 | 复现性 |
| judge3 | **blind2（标签互换）** | **苛刻**：明确警告"更长更用力不等于更好"、"刻意留白/意味深长的动作收尾"要扣分 | 抗风格偏好 |
| judge4 | blind2（标签互换） | 中性 | **控制位置偏差** |

- **标签互换**：judge3/4 看到的"甲"是 judge1/2 看到的"乙"。如果评审只是偏好"甲"这个位置，换位后结论会翻转。
- **苛刻提示**：judge3 被要求主动怀疑"高级写法"。它衡量的是：当评审带着敌意读时，B 的优势还剩多少。
- 四位评审均不知道作者、不知道分组、不知道其他评审的结论；被禁止读取 `key.json` 与 `runs/`。

### 5.2 评价维度（八个，强制二选一）

继续阅读意愿 / 人物鲜活度 / 场景可感度 / 情节推进自然度 / 情绪感染力 / 语言自然度 / 堆砌与注水（少者胜） / 题材与约束契合。

**为什么用强制选择而不是 1–10 打分**：打分会出现尺度漂移（同一篇在不同评审手里差 3 分），强制选择的信息量更大，也更难"和稀泥"。允许"平"，但限制次数（十组最多两次），防止退化成全部平局。

### 5.3 评审要求的证据质量

每位评审的 `reason` 必须引用具体句子，`key_diff` 必须一句话指出关键差异。汇总时检查：理由里有没有引文。没有引文的判断不计入定性分析。

## 6. 客观侧：脚本做什么、不做什么

`scripts/craft_lint.py` 输出描述性指标，不做质量分：

| 类别 | 指标 |
|---|---|
| 句法 | 句长均值／中位数／P90／CV、短句占比、长句占比、最长句 |
| 段落 | 段长均值／CV、单句成段占比 |
| 对话 | 对话字符占比、对话标签分布 |
| 词汇 | "的"密度、程度副词、情绪命名、身体反应、解释性标记、套话、抽象后缀 |
| 结构 | 四字片段重复、三连排比、"不是A而是B"、破折号／省略号／感叹号密度 |
| 感官 | 视／听／嗅／味／触五通道词频 |
| 模式专项 | 小说：对话占比过低提示；历史+古代：现代词汇（时代错置）提示 |

`experiments/tools/analyze.py` 另外做**硬约束检查**：字数区间、必须保留的事实（润色）、必须清除的词（润色）、数字数量、金额数量、对话占比。

**脚本明确不做的**：判断好不好、给分数、认定不合格。所有 flag 都是"提示"。阈值取的是极端值，落在阈值内不代表好。

## 7. 统计口径（三个数字不能混用）

这是本文件最容易被误读的地方。三类指标测的不是一回事：

| 指标 | 怎么来的 | 能说明什么 | 不能说明什么 |
|---|---|---|---|
| **模型相对偏好比例** | 盲评二选一的胜率（如第一轮 32/40、第二轮 16/21） | 同一模型评审在两篇之间更愿意保留哪篇 | 人类读者会喜欢哪篇 |
| **硬约束通过率** | 脚本检查：字数区间、必留事实、禁用词、数字数量 | 任务里能写成规则的要求，有没有被遵守 | 文本好不好读 |
| **真实用户阅读意愿** | 需要真人读者，目前**没有** | —— | —— |

**报告时必须写清用的是哪一个。** 把 76% 写成"读者更喜欢"是造假。

其他约定：

- 总评：每位评审每个场景一票，平局单列。
- 分维度：按维度累计，报 B 胜率（去掉平局）。
- **方向稳定**：≥3/4 评审同向的场景计为"稳定"。这比总胜率更能说明改善是否可靠。
- 评审一致性：维度级两两成对一致率。
- 不做显著性检验：10 个场景、非独立（同一模型既写又评），做 p 值是伪精确。
- **各轮不合并统计**：第二、三轮都是另行写定的测试集（见 `ROUND2.md`、`ROUND3.md`），各自并列报告，不累加成 18 个场景。
- **不称「预注册」**：这些场景在生成前写定，但没有第三方时间戳，也没有对外登记。严格意义上的预注册需要可验证的时间证明，本仓库不具备。
- **不把模型判断当人类样本**：同一模型的多次判断只反映该模型的偏好，不能叠加成「读者共识」。

## 8. 效度威胁（这一节比结果重要）

按严重程度排序：

1. **同模型自评**。评审与写作是同一个模型家族。模型很可能偏好自己（以及自己写的 skill）产出的语式——尤其是"克制的短句 + 动作收尾"这一路。这是最大的威胁，**没有消除**。
   - 计划中本应有一个跨厂商模型（GPT 系）做独立评审；按用户指示未调用 codex，因此**本轮没有跨模型证据**。
2. **作者即评审设计者**。skill 是我写的，评价标准也是我定的（虽然具体判定由隔离上下文的评审完成）。标准本身可能偏向 skill 的强项（例如把"人物欲望"设为维度之一）。
3. **样本小且非随机**。10 个场景、每个场景每臂只生成 1 篇。单篇方差很大，一次生成的好坏可能盖过方法的效果。
4. **长度混杂**。B 组普遍更长（S02 +20%，S03 +18%，S06 +11%）。评审可能把"更长"误读为"更充实"。S07（B 更长却只打成 2–2）说明长度不是决定因素，但没有做严格的长度匹配实验。
5. **体裁新颖性**。任务书本身是"文学性"的，模型在裸写时也会往文学方向走，A 组并不弱。这会让差异变小，而不是变大——所以观察到的差异不像是任务暗示造成的。
6. **单轮生成**。真实使用中作者会改稿。本实验比较的是"一次成型"，不是"最终稿"。
7. **v0.1.1 的重测是事后补救**。三个失败场景的修复是在看到结果之后做的，只做了探索性重测（n=3，每场景 2 位评审），**不能当作确认性证据**。

## 9. 复现

```bash
cd LITERARY_CRAFT_20261028

# 1. 生成 20 份 prompt（A/B 逐字相同，B 多一段 skill 说明）
python experiments/tools/build_prompts.py

# 2. 由写作代理按 prompts/*.txt 写入 runs/<sid>/<arm>.md
#    （本仓库已包含本轮全部成品，可直接复算）

# 3. 匿名化
python experiments/tools/blind.py

# 4. 客观侧
python experiments/tools/analyze.py
#    → experiments/metrics.csv / checks.csv / metrics.md

# 5. 盲评（由评审代理写入 judgments/judge*.jsonl）

# 6. 汇总（含换位检验）
python experiments/tools/aggregate.py
#    → experiments/judgments/summary.md / summary.json

# 7. skill 自身回归测试
cd literary-craft && python -m unittest discover -s tests -v
```
