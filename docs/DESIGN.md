# 设计思路与适用边界

## 1. 问题定义

要解决的不是"AI 味"，也不是"细节不够"。

真实的失败长这样：

- 读完一段，读者不想知道后面怎样了。
- 人物在做事，但看不出他想要什么。
- 场景写得很满，但没有任何东西是必需的。
- 情绪写得很足，读者一点感觉都没有。
- 句子都很漂亮，连起来是一篇谁写的都行的文章。

这些不是语言问题，是**结构问题**。所以这个 skill 不从词汇表下手，从"读者为什么还要读下一段"下手。

**明确的取舍**：本 skill 不追求"句子级的美"。它优先保证文本有驱动力、人物有欲望、细节承重、情绪有证据。文学性上限靠作者天赋，工具只能抬下限。

## 2. 为什么核心概念是"落差"，而不是"冲突"

"冲突"是一个小说中心的概念。它解释不了散文，也解释不了历史叙事——历史事件的结局是公开的，哪来的悬念？

"落差"能覆盖全部五种模式：

| 模式 | 落差在哪 |
|---|---|
| 小说 | 读者不知道结果；人物想要的 vs 得到的 |
| 历史叙事 | 读者知道结局，人物不知道（戏剧反讽）；史料记载 vs 史料空白 |
| 散文 | 读者的理解 vs 文本给出的理解（认知落差） |
| 润色 | 原文哪里已经把落差讲平了 |
| 编辑 | 诊断"落差缺失／过早闭合／过密" |

**这个抽象带来的直接好处**：五个模式共用一套诊断语言，但**评价标准仍然分开**（见第 4 节）。统一的是提问方式，不是答案。

### 落差的三种死法

这是本 skill 最有操作性的部分，因为它把"写得平淡"这种模糊评价，拆成了三个可定位的故障：

1. **提前关闭**：刚提出就解释完。
2. **虚假落差**：提了不兑现，或兑现得太容易。
3. **落差过密**：同时开五条线，读者不知道等哪个。

## 3. 架构与 token 预算

```
literary-craft/
├── SKILL.md                    核心模型 + 路由 + 自检（常驻上下文）
├── references/
│   ├── fiction.md              小说
│   ├── history.md              历史叙事
│   ├── essay.md                散文
│   ├── revise.md               润色
│   ├── edit.md                 文学编辑
│   ├── anti-patterns.md        15 组病灶图鉴
│   └── rhythm.md               中文节奏的具体问题
├── scripts/craft_lint.py       表层体检（只提示）
└── tests/                      回归测试 + 10 个场景
```

**渐进式加载**：

- 触发时只加载 `SKILL.md`（约 2.5k tokens）。
- 按路由最多再加载 **2 份** reference（每份 1.5–3k tokens）。
- 峰值约 8k tokens。对比"把所有内容塞进一个文件"（估计 20k+），省一半以上。

**为什么不做 few-shot 范文**：范文会让模型模仿**那一篇的腔调**，而不是学方法。用户明确说"不是让 AI 写得像某位作家"。所有示例都是原创的短句对照，服务于"判断"，不服务于"模仿"。

**为什么脚本只做提示、不打分**：一旦有分数，用户和模型都会为分数写作。句长均匀在某些段落是正确选择，形容词多在某些文体是必要的。打分器会把复杂的判断压成一个数字，那是伪精确。

## 4. 五个模式，五套标准

一套模板通吃是这类 skill 最常见的失败。本 skill 给每个模式单独定了**不合格线**：

| 模式 | 不合格线（不是风格建议） |
|---|---|
| 小说 | 没有具体欲望；场景结束没有状态变化；对话只交换信息；结尾总结主题 |
| 历史 | 给真实人物编直接引语当史料；时代错置；数字含糊到无法核对 |
| 散文 | 读完没有多知道任何东西；联想与材料无因果；升华到"人生"而材料撑不住 |
| 润色 | 改动事实／视角／篇幅 ±20% 以外；无故扩写 |
| 编辑 | 评价不指向具体句子；只给一个方案；把偏好写成错误 |

这些线的作用是**否决**，不是评分。一条不过，就不该交付——先改结构，不要润色句子。

---

## 5. 为什么不做强制预写流程

用户明确要求："不要依赖大量强制性的预写作步骤。如果某种流程明显增加延迟或 Token，却不能改善结果，应删去。"

本 skill 因此**没有**：人物小传模板、三幕结构表、场景卡片、写作前问卷。

保留的只有一个内部判断，且不输出给用户：

- 小说：这场戏结束时，谁的处境变了？
- 散文：读完读者多知道了哪一件具体的事？

**代价**：没有流程兜底，模型在特别模糊的需求下可能仍然写得散。这是已知缺陷，见 `RESULTS.md`。

---

## 6. 反公式化条款：为什么它是必需品而不是装饰

一个只教技巧的 skill 会产出"技巧展示体"：句子都在用力、每段都有金句、每个细节都在暗示、结尾一定要回环。

这种文本比平庸更难读，因为它让读者一直意识到"有人在写"。

所以 SKILL.md 第 5 节给了五条**反向操作**，其中第 5.1 条（设计感收尾）是实测之后补的：

> 回环收尾和无言定格，是写作课的标准答案，也因此最容易被识破。判断标准：这个收尾是人物处境自然产生的，还是你为了让全篇完整而摆上去的？

这条来自第一轮 A/B 测试的失败案例（S01、S06、S07 三个场景里，B 组有两篇用了设计过的回环或定格，评审明确说"更像设计，不像生活"）。

## 7. 关键取舍（我放弃了什么）

| 放弃 | 原因 |
|---|---|
| 文风模仿 | 六部作品风格互斥，模仿会得到矛盾指令；且用户明确不要 |
| 评分器 | 会诱导为分数写作（见第 3 节） |
| 强制预写流程 | 增加延迟与 token，收益未证实 |
| 长范文 few-shot | 会带来腔调迁移，与"不模仿"冲突 |
| 覆盖公文／论文／文案 | 没有语料，硬套会变差；明确写进边界 |
| 自动改写全文 | 润色场景里这是越权（见 revise.md 第 6 节） |

## 8. 适用边界

**适用**：

- 1000–5000 字的中文短篇、散文、历史叙事片段
- 已有文本的润色与诊断
- 需要"能读下去"而不是"能发表"的场合

**不适用**：

- 公文、申论、学术论文、商业文案、技术文档（方法与语料都不对）
- 诗歌与格律（未研究）
- 超长篇（10 万字以上）的结构管理（本 skill 只管场景级，不管卷级）
- 需要严格事实核查的出版级历史写作（本 skill 提供纪律，不提供考据能力）

**能力边界要说清**：

- 它能减少结构性缺陷，**抬不高上限**。
- 它不能替代作者的生活经验。写不出的细节，工具变不出来。
- 它在"约束很多的命题写作"上表现不稳定（实测约束契合维度只有 57% 胜率），见 `RESULTS.md`。

## 9. 与 `ziyue-voice` 的分工

| | ziyue-voice | literary-craft |
|---|---|---|
| 目标 | 像**某个人**写 | 让文本**值得读** |
| 依据 | 6 份本人语料的实测指纹 | 跨作品的机制抽象 |
| 冲突时 | 以"像"为准 | 以"读者体验"为准 |

两者可以叠加使用：先用 literary-craft 解决结构与驱动力，再用 ziyue-voice 调整到个人腔调。**顺序不能反**——先调腔调再改结构，等于白调。
